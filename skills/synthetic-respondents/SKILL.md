# Synthetic respondents: hypothesis generation only

## Boundary

AI personas are fictional simulation prompts, not recruited people, user
research, observations, market measurements, or evidence of demand or
prevalence. Never invent an interview quotation and attribute it to a real
participant. Never use a persona response to upgrade a claim's confidence.
Do not place synthetic responses in evidence as facts.

## Procedure

1. Read the approved brief and state the research question and what real-world
   uncertainty it is intended to explore.
2. If preparing real interviews, create a neutral discussion guide: consent
   and privacy introduction, open questions, recent-behavior probes, and
   non-leading follow-ups. Real interviews require informed consent; exclude
   personal data from repository artifacts.
3. For a simulated interview, define a clearly fictional persona as an
   assumption-based perspective. Avoid demographic or behavioral stereotypes.
   Ask open-ended questions, allow uncertainty and disagreement, and do not
   prime a preferred product or strategy. Run multiple materially different
   personas only to discover possible objections and alternative hypotheses.
4. Label all output prominently **SYNTHETIC — NOT A REAL INTERVIEW**. Preserve
   the persona assumptions and prompt context. Summarize candidate questions,
   vocabulary, objections, or hypotheses; do not report fabricated prevalence
   or numerical demand.
5. If a useful candidate hypothesis is added to
   `state/evidence_graph.json`, use `type: "hypothesis"`, `confidence: "low"`,
   and a note that it was generated by a synthetic persona and requires
   validation with real people or behavioral data. A `synthetic://` source
   locator may document the simulation, but is not a real-world source and
   must never support a fact.
6. Validate claims normally. If the schema or validation process would make a
   synthetic response appear to be a factual source, omit it from the evidence
   graph and keep it in a clearly labeled hypothesis artifact instead.

## Stop for the user

Ask for approval before recruiting or contacting real participants, recording,
or handling identifiable interview data. If a user requests synthetic
responses be represented as real evidence, refuse that representation and
offer a clearly labeled hypothesis-generation alternative.

## Output

Save guides and simulation notes only as clearly labeled project artifacts.
Report which follow-up real-world observation could falsify each generated
hypothesis.
